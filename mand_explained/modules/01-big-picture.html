The Big Picture

What ./cub3D actually does between the moment you launch it and the moment a 3D corridor appears — the program lifecycle and the frame pipeline.

A 3D world from a 2D text file

Cub3D is a raycasting engine. The world is just a grid of characters — 1 is a wall, 0 is floor — and yet the player walks through it in first person. The whole trick: 1280 rays per frame, one per screen column, each answering a single question: "how far is the nearest wall in this direction?"

🎯
Evaluator question #1 (it always comes first)

"Walk me through your program from main() to the first frame." This module is exactly that answer. If you can narrate the two diagrams below from memory, you've passed the opening question.

📜
Parser — src/parsing/

Reads the .cub file once at startup. Either produces a fully validated map + config, or prints Error\n and exits. Nothing invalid survives past this point.

🧭
Player state — t_player

Five doubles, no angles: position (pos_x, pos_y), direction vector (dir), camera plane vector (plane). The entire camera model.

📡
Raycaster — src/execution/

For each screen column: build a ray, run DDA until it hits a 1, report distance and which wall face was hit.

🖼️
Renderer — src/render/

Turns each ray result into one vertical stripe: ceiling color on top, textured wall slice in the middle, floor color below. Writes pixels into an off-screen image.

⌨️
Events — src/events/

MLX hooks that record which keys are held, and per-frame functions that turn held keys into movement and rotation.

Boot sequence: six calls, in order

main() is deliberately boring — it's a checklist. Order matters and evaluators love asking why.

src/main.c 

cub_init(&cub);
parse_file(&cub, av[1]);
init_mlx(&cub);
load_textures(&cub);
register_hooks(&cub);
mlx_loop(cub.mlx);
PLAIN ENGLISH

Zero the whole struct with ft_bzero — so cleanup can safely check "was this ever allocated?" on any field, even after an early error.

Parse and validate everything before opening a window. Bad file → error and exit without ever touching graphics.

Connect to the display server, open the 1280×720 window, create the off-screen image buffer.

Load the 4 wall XPM textures — needs MLX alive, hence after init_mlx.

Register key press/release, window close, and the per-frame loop callback.

Hand control to MLX forever. From here on, everything happens inside callbacks.

💡
Why parse before MLX?

Two reasons: a bad map must fail fast with only Error\n + message (no window flash), and error cleanup is much simpler when there are no graphics resources to undo yet. cub_init's zeroing is what makes exit_error → cub_destroy safe at any point: every destroy is guarded by if (ptr).
