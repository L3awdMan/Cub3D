Module 3 · Movement & rotation

A box on graph paper that walks and spins.

The player isn't a model with feet — it's two 2D vectors. dir points where you're facing. plane is a sideways vector perpendicular to dir that defines the FOV. Move the player by adding a scaled copy of either vector to their position. Rotate by multiplying both vectors through a 2D rotation matrix. That's the whole game of movement.

Held-key state, not key events

cub3D doesn't move you on KeyPress. It marks the key as "currently held" and lets the per-frame loop sample that state every time. Smooth movement, no autorepeat lag.

CODE — hooks.c:24 
int	key_press(int key, void *param)
{
	t_cub	*cub;

	cub = (t_cub *)param;
	if (key >= 0 && key < 65536 && !cub->keys[key])
	{
		if (key == KEY_M)
			cub->show_minimap = !cub->show_minimap;
		if (key == KEY_E)
			toggle_door(cub);
	}
	if (key >= 0 && key < 65536)
		cub->keys[key] = 1;
	if (key == KEY_ESC)
		close_hook(param);
	return (0);
}

X11 calls this for every KeyPress.

🔘
Edge-trigger vs level-trigger

Movement keys are "level-triggered" — read every frame while held. Toggles (door, minimap) are "edge-triggered" — only the moment the key goes from up to down counts. The !cub->keys[key] check before flipping is the edge gate.

apply_movement — one key, one vector

W and S walk along your facing direction. A and D strafe along the camera plane (which is perpendicular to dir). The sign argument flips forward into backward, left into right.

CODE — movement.c:87 
void	apply_movement(t_cub *cub)
{
	if (cub->keys[KEY_W])
		move_along(cub, cub->player.dir_x, cub->player.dir_y, 1);
	if (cub->keys[KEY_S])
		move_along(cub, cub->player.dir_x, cub->player.dir_y, -1);
	if (cub->keys[KEY_A])
		move_along(cub, cub->player.plane_x, cub->player.plane_y, -1);
	if (cub->keys[KEY_D])
		move_along(cub, cub->player.plane_x, cub->player.plane_y, 1);
}
PLAIN ENGLISH

Once per frame, react to held movement keys.

W held → walk along the forward vector.

Direction = dir, sign = +1.

S held → walk along the forward vector backwards.

Same vector, sign = −1.

A held → strafe along the sideways plane vector backwards.

Plane vector, sign = −1.

D held → strafe forward along the plane vector.

Plane vector, sign = +1.

move_along — slide axes independently

Here's the subtle bit. The proposed new X and new Y are checked separately. If X is fine but Y is into a wall, you slide along X. That's why you can rub against a wall and slip around it instead of stopping dead.

CODE — movement.c:67 
static void	move_along(t_cub *cub, double vx, double vy, int sign)
{
	double	nx;
	double	ny;

	nx = cub->player.pos_x + sign * vx * MOVE_SPD;
	ny = cub->player.pos_y + sign * vy * MOVE_SPD;
	if (can_move(cub, nx, cub->player.pos_y))
		cub->player.pos_x = nx;
	if (can_move(cub, cub->player.pos_x, ny))
		cub->player.pos_y = ny;
}
PLAIN ENGLISH

Try to move the player along (vx, vy), flipped by sign.

Where we'd land on X.

Where we'd land on Y.

New X = old X + sign × vx × speed.

New Y = old Y + sign × vy × speed.

Test the X move on its own (keep old Y).

If OK, commit the X.

Then test the Y move on its own (using whatever X we just committed).

If OK, commit the Y.

🧱
Why split the X and Y collision tests?

If you tested the new (X, Y) as a single point, hitting a wall would stop you cold. Testing X and Y independently means you keep whichever component didn't hit, so you smoothly slide along the wall. Every shooter does this; cub3D's version is six lines.

can_move & corner_blocked — bounding-box collision

The player isn't a point — it's a small square with side 2 × COLLISION = 0.4 cells. can_move checks all four corners against the map. If any corner sits in a wall, an OOB cell, or a not-yet-open door, the move is rejected.

static int	corner_blocked(t_cub *cub, double x, double y)
{
	t_map	*map;
	int	mx;
	int	my;
	char	c;

	map = &cub->map;
	mx = (int)x;
	my = (int)y;
	if (my < 0 || my >= map->height)
		return (1);
	if (mx < 0 || mx >= (int)ft_strlen(map->grid[my]))
		return (1);
	c = map->grid[my][mx];
	if (c == '1')
		return (1);
	if (c == 'D' && !door_is_open(cub, my, mx))
		return (1);
	return (0);
}

Rotation is a single matrix multiply

To rotate by angle α, both dir and plane are multiplied through the same 2D rotation matrix. They stay perpendicular because the same orthogonal transformation is applied to both.

∑
The 2D rotation matrix

new_x = old_x · cos(α) − old_y · sin(α)
new_y = old_x · sin(α) + old_y · cos(α)

Apply it to both your direction vector and your camera plane. The pair stays perpendicular because rotation preserves angles.

CODE — rotation.c:28 
void	rotate_vectors(t_player *p, double angle)
{
	double	old_dir_x;
	double	old_plane_x;
	double	cos_a;
	double	sin_a;

	cos_a = cos(angle);
	sin_a = sin(angle);
	old_dir_x = p->dir_x;
	p->dir_x = old_dir_x * cos_a - p->dir_y * sin_a;
	p->dir_y = old_dir_x * sin_a + p->dir_y * cos_a;
	old_plane_x = p->plane_x;
	p->plane_x = old_plane_x * cos_a - p->plane_y * sin_a;
	p->plane_y = old_plane_x * sin_a + p->plane_y * cos_a;
}
PLAIN ENGLISH

Rotate the player's dir + plane vectors by angle radians.

Stash the old X components — the formula needs the original value of one while computing the other.

Compute cos and sin once each (cheaper than calling them twice).

Save dir_x before overwriting it.

Apply the rotation matrix's first row to dir.

Second row (uses the original dir_x via old_dir_x).

Same dance for the plane vector.

First row.

Second row.

⚠️
Watch the variable swap

Notice old_dir_x being saved before the first overwrite. If you skip that and compute dir_y using the just-updated dir_x, the second equation reads the wrong value and your rotation slowly drifts the vector lengths to zero. Same trap as swapping two variables without a temp.

Two callers: keyboard + mouse

rotate_vectors is de-static'd specifically so the mouse module can call the exact same function with a different angle. Same math, two input devices, zero duplication.

void	apply_rotation(t_cub *cub)
{
	if (cub->keys[KEY_LEFT])
		rotate_vectors(&cub->player, -ROT_SPD);
	if (cub->keys[KEY_RIGHT])
		rotate_vectors(&cub->player, ROT_SPD);
}
PLAIN ENGLISH

Once per frame, react to held arrow keys.

Left arrow held → rotate by a negative small angle (counter-clockwise).

Right arrow held → rotate by a positive small angle (clockwise).
