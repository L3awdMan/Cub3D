Module 6 · Minimap

A circular cookie cutter stamped onto a square grid.

The minimap is built as a square in memory — cells, player marker, FOV cone, white ring — but every single pixel write is gated by one Euclidean distance test against the disc center. Outside the disc? silent drop. Inside? written. That's the entire technique. No alpha mask, no second image, no MLX trickery.

The geometry

MM_X, MM_Y Top-left screen position of the minimap bounding box. (16, 16) — tucked under the corner.
MM_SIZE Bounding-box side length in pixels. 108.
MM_R Disc radius. 54 = half of MM_SIZE.
center (MM_X + MM_R, MM_Y + MM_R) = (70, 70). The center of the disc on screen.
MM_CELL Pixels per map cell drawn on the minimap. 9.
MM_RADIUS How many cells in each direction from the player are visible. 6.

The cookie cutter — mm_in_circle

For a candidate pixel (x, y), compute its offset (lx, ly) from the disc center. If lx² + ly² ≤ MM_R², the pixel is inside. Plain integer arithmetic — no sqrt, because comparing squared distances against squared radius gives the same answer faster.

CODE — minimap_draw_bonus.c:24 
static int	mm_in_circle(int x, int y)
{
	int	lx;
	int	ly;

	lx = x - (MM_X + MM_R);
	ly = y - (MM_Y + MM_R);
	return (lx * lx + ly * ly <= MM_R * MM_R);
}

Pythagoras squared: inside if lx² + ly² ≤ R².

√
Why not sqrt?

The condition distance ≤ R is equivalent to distance² ≤ R² whenever both sides are non-negative. Squaring is one multiply; sqrt is a much more expensive transcendental. For a 108×108 box at 60 FPS, that adds up.

Every minimap write goes through mm_put_circ

		put_px(&cub->img, x, y, c);
}

The four passes that build the minimap

1
Cell grid

draw_minimap walks a window of 2 × MM_RADIUS cells around the player and stamps each as a colored MM_CELL square via mm_square.

2
FOV cone + facing line

mm_overlay calls mm_ray three times: left FOV edge in blue, right FOV edge in blue, forward facing in red.

3
Player dot

A 5×5 yellow patch centered on the disc center.

4
White outer ring

mm_outline writes only pixels in the band between R − 3 and R — that's the 3-pixel-thick white frame on top.

draw_minimap — the orchestrator

CODE — minimap_bonus.c:75 
void	draw_minimap(t_cub *cub)
{
	double	px;
	double	py;
	int	gy;
	int	gx;

	if (!cub->show_minimap)
		return ;
	px = cub->player.pos_x;
	py = cub->player.pos_y;
	gy = (int)(py - MM_RADIUS) - 1;
	while (++gy <= (int)(py + MM_RADIUS))
	{
		gx = (int)(px - MM_RADIUS) - 1;
		while (++gx <= (int)(px + MM_RADIUS))
			mm_square(cub, MM_X + (int)((gx - (px - MM_RADIUS)) * MM_CELL),
				MM_Y + (int)((gy - (py - MM_RADIUS)) * MM_CELL),
				mm_cell_color(cub, gy, gx));
	}
	mm_overlay(cub);
	mm_outline(cub);
}

The FOV cone — mm_ray

Plotting "a line from center toward direction (vx, vy)" is dead simple: step a parameter t in tiny increments, multiply by the direction vector and the cell size, write a pixel. The disc mask handles clipping for free.

CODE — minimap_draw_bonus.c:66 
void	mm_ray(t_cub *cub, double vx, double vy, unsigned int color)
{
	double	t;
	int	sx;
	int	sy;

	t = 0.0;
	while (t < MM_RADIUS - 0.5)
	{
		sx = MM_X + MM_SIZE / 2 + (int)(vx * t * MM_CELL);
		sy = MM_Y + MM_SIZE / 2 + (int)(vy * t * MM_CELL);
		mm_put_circ(cub, sx, sy, color);
		t += 0.04;
	}
}
PLAIN ENGLISH

Plot a line from the disc center along (vx, vy).

Parameter starts at 0.

Step until we'd exit the disc (≤ MM_RADIUS - 0.5 cells out).

Screen X = center + (vector × t × pixels-per-cell).

Same for Y.

Write — silently dropped if outside the disc.

Small step. Smaller = denser pixels.

mm_overlay sends three rays

The player's facing direction is dir. The two FOV edges are dir + plane and dir − plane — that's the same camera math the raycaster uses for the leftmost and rightmost screen columns.

The white ring — mm_outline

A ring is "inside the outer disc AND outside a slightly smaller inner disc." One squared-distance test, two thresholds.

⚪
Ring as a band

(R − 3)² < lx² + ly² ≤ R²

R = 54. Inner = 51. Pixels with squared distance in (2601, 2916] get white. Everything else is left untouched (it's already cells / overlay / unwritten).

CODE — minimap_draw_bonus.c:86 
void	mm_outline(t_cub *cub)
{
	int	x;
	int	y;
	int	lx;
	int	ly;
	int	d2;

	y = MM_Y - 1;
	while (++y < MM_Y + MM_SIZE)
	{
		x = MM_X - 1;
		while (++x < MM_X + MM_SIZE)
		{
			lx = x - (MM_X + MM_R);
			ly = y - (MM_Y + MM_R);
			d2 = lx * lx + ly * ly;
			if (d2 <= MM_R * MM_R
				&& d2 > (MM_R - MM_RING_THICK) * (MM_R - MM_RING_THICK))
				put_px(&cub->img, x, y, MM_RING);
		}
	}
}
