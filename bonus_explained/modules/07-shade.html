Module 7 · Shade & head bob

Three tiny tricks that make flat pixels feel like a corridor.

Walls are textured. Doors slide. The minimap shows you a disc of map. None of that, by itself, feels three-dimensional. Three small effects close the gap: depth fog (far things go dark), a North/South darkening trick from Wolfenstein, and a sine-wave head bob that rocks the horizon while you walk. Each is a few lines of math.

The per-channel multiplier — shade_rgb

Almost every shaded pixel in the game is just texel × k, where k is a number between 0 and 1. Multiply each of the R, G, B channels independently by k, clamp back to [0, 255], repack. Black at k = 0, original color at k = 1.

CODE — shade.c:25 
unsigned int	shade_rgb(unsigned int color, double k)
{
	int	r;
	int	g;
	int	b;

	r = (int)(((color >> 16) & 0xFF) * k);
	g = (int)(((color >> 8) & 0xFF) * k);
	b = (int)((color & 0xFF) * k);
	if (r < 0) r = 0;
	if (g < 0) g = 0;
	if (b < 0) b = 0;
	if (r > 255) r = 255;
	if (g > 255) g = 255;
	if (b > 255) b = 255;
	return ((unsigned int)((r << 16) | (g << 8) | b));
}
PLAIN ENGLISH

Multiply an RGB color by k, clamp, return the new RGB.

Extract red channel (bits 16–23) and scale.

Green (bits 8–15).

Blue (bits 0–7).

Underflow guard.

Overflow guard so a k > 1 (e.g. flash effect) doesn't roll into the next byte.

Repack into a single 0xRRGGBB.

🎨
Why channels independently?

A pixel color is three numbers in one int: red, green, blue. Scaling them in lockstep dims the whole color uniformly toward black. Scaling them differently would tint the color — useful for sunset effects, but cub3D wants plain darkening.

Trick 1 — Depth fog

Far walls should be dark, close walls bright. The formula is simply fog = min(1, FOG_K / perp_dist). At perp_dist ≤ FOG_K = 6 (six cells away) the wall is at full brightness. Beyond that, brightness falls off as 1 / distance. Multiply the texel by that and you've got fog.

	dw->shade *= SIDE_SHADE;

Trick 2 — Wolfenstein side darkening

Faces hit on the X axis (East/West) and faces hit on the Y axis (North/South) get different brightness. Same texture, but one set rendered at 0.55 × brightness. The eye reads that as a corner — adjacent walls look like adjacent walls, not one continuous flat sheet. Wolfenstein 3D did this in 1992 and it still works.

🧱
Why this sells "corner-ness"

In real life, light from above falls more directly on horizontal-facing walls than on perpendicular ones. The brain expects the contrast. Without side darkening, two adjacent textured walls bleed into one ambiguous shape; with it, the corner pops.

Trick 3 — Head bob

The "horizon" — the Y coordinate where ceiling meets floor — is normally just WIN_H / 2. The bonus build adds a sin wave on top, advancing the phase only while a WASD key is held. Walk → horizon sways → walls slide up and down a few pixels → you feel like you're walking.

CODE — shade.c:79 
void	update_horizon(t_cub *cub)
{
	int	moving;

	moving = cub->keys[KEY_W] || cub->keys[KEY_S]
		|| cub->keys[KEY_A] || cub->keys[KEY_D];
	if (moving)
		cub->bob_t += BOB_STEP;
	cub->horizon = WIN_H / 2 + (int)(sin(cub->bob_t) * BOB_AMP);
}
PLAIN ENGLISH

Per-frame: nudge the head-bob phase, recompute the horizon.

Any WASD key held?

Advance the sine phase only while moving (so view sits still when stopped).

Horizon = screen middle + sin(phase) × 5 px. ±5 pixel sway, ~0.18 radians per frame.

📈
Why advance phase only while moving

If bob_t always ticked, the world would bob even when you stood still. Gating advance on "is a movement key held" makes the bob feel coupled to actual locomotion. The phase persists, so when you start walking again you continue the wave instead of snapping back to zero.

Where everything plugs into the wall stripe

The same dw->shade field carries the combined fog × side-darkening multiplier. The texture column drawer reads it once per row of the stripe and multiplies every texel through shade_rgb.

CODE — draw_wall.c:63 
static void	draw_tex_col(t_cub *cub, int x, t_draw *dw, t_img *tex)
{
	int	y;
	int	tex_y;
	unsigned int	color;

	y = dw->start;
	while (y <= dw->end)
	{
		tex_y = (int)dw->pos;
		if (tex_y >= tex->height)
			tex_y = tex->height - 1;
		if (tex_y < 0)
			tex_y = 0;
		color = shade_rgb(get_tex_pixel(tex, dw->tex_x, tex_y), dw->shade);
		put_px(&cub->img, x, y, color);
		dw->pos += dw->step;
		y++;
	}
}
PLAIN ENGLISH

Paint one vertical wall column.

Start at the top of the stripe.

Walk down to the bottom.

Sample row in the texture (pos is a fractional accumulator).

Clamp top.

Clamp bottom.

Sample the texel + apply the per-column shade.

Write to the frame buffer.

Advance the texture-row accumulator by the per-pixel step.

Fog for the floor + ceiling too

The floor/ceiling textures get the same treatment, but with a slightly different formula. Because background pixels can be arbitrarily far away, dividing by (FOG_K + rd) instead of just FOG_K / rd bounds the multiplier in (0, 1) for any rd ≥ 0 — no overflow, smooth fall-off all the way to the horizon.

CODE — draw_bg.c:52 
return (shade_rgb(get_tex_pixel(tex,
			((int)(tw * (fx - floor(fx)))) & (tw - 1),
			((int)(tw * (fy - floor(fy)))) & (tw - 1)),
		FOG_K / (FOG_K + rd)));
PLAIN ENGLISH

Sample the floor/ceiling texel and shade it by depth fog.

Wrap fx into [0, tex_width) using bit-mask AND (works because tw is power-of-two).

Same for fy.

Fog multiplier: FOG_K / (FOG_K + rd) — always in (0, 1].

∞
Two fog formulas, same vibe

Walls use min(1, FOG_K / d) — full brightness up close, then 1/d. Floor uses FOG_K / (FOG_K + d) — always less than 1, smooth from horizon outward. Different choice, same goal: bound brightness, sell depth.
