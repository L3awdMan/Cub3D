Parser extensions over the mandatory format

The bonus keeps the mandatory elements (NO/SO/WE/EA textures, F/C colours) but adds tolerance and one new directive. First, identifiers may be followed by any whitespace, not just a single space — so a tab-separated NO\t./tex.xpm is now valid.

CODE — parse_elements.c:10 
static int	matches_id(const char *s, const char *id, int len)
{
	return (ft_strncmp(s, id, len) == 0 && ft_isspace((unsigned char)s[len]));
}
PLAIN ENGLISH

Does the line start with identifier `id`...

...and is the very next char whitespace? (space OR tab) Then it matches.

📝
Order matters in identify_element

FLOOR is checked before F. If F came first, matches_id(line, "F", 1) would never fire for a FLOOR line — wait, actually it would fail because the char after F isn't whitespace (FLOOR → F followed by L). The explicit FLOOR-first ordering plus the whitespace check is what keeps the single-letter F/C colours from swallowing longer keywords.

The FLOOR <n> directive

This is the bonus's custom element. It sets cub->floor, which (Module 9) decides the entire per-floor art table. The subject explicitly permits extending the scene format for the bonus.

CODE — parse_elements.c:46 
void	parse_floor(t_cub *cub, char *line)
{
	while (*line && ft_isspace(*line))
		line++;
	line += 5;
	while (*line && ft_isspace(*line))
		line++;
	n = ft_atoi(line);
	if (n < 1)
		exit_error(cub, "Invalid FLOOR number");
	cub->floor = n;
}
PLAIN ENGLISH

Parse "FLOOR <n>".

Skip leading whitespace...

...skip the 5 letters of "FLOOR"...

...skip the whitespace before the number.

Read the number.

Below 1 is nonsense → hard error.

Store it — this selects the floor's art/theme.

⚡
FLAG_ALL = 63 — and FLOOR is not in it

63 is binary 111111 — bits 0–5: the four textures plus F and C. Notice parse_floor never touches parsed_flags, so the FLOOR directive is optional and defaults to 1. A map with no FLOOR line still parses fine; it just runs as floor 1. After the map is stored, post_map_check rejects any further non-blank line as "Content after map" — no trailing junk allowed.

💡
The order IS the architecture

Read those two lists top-to-bottom and the dependencies fall out: walls before sprites (z-buffer), sprites before projectiles (shared depth), world before HUD (overlay on top), flashes before bars (vignette under the UI), everything before the crosshair, then exactly one mlx_put_image_to_window. The state dispatch in loop_hook means cutscene and menu states swap in their own draw and skip all of this — one integer, the whole program.
