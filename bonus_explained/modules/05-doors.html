Module 5 · Doors

A door that retracts from its middle — and lets rays through the slit.

The door is a 1×1 cell tagged 'D' in the map. It has one number — progress, from 0.0 (closed) to 1.0 (fully open) — and one target. Each frame the progress eases toward its target. The clever part: while the door is mid-open, the renderer lets rays pass through the retracted middle band and stop on the still-solid sides. That's how you can see the room behind a half-open door and still see the door's edges sliding away.

Three files, three responsibilities

⚙️
doors_bonus.c

State + animation. Allocates the door grid; advances progress toward target every frame at DOOR_SPEED.

👆
door_use_bonus.c

Player input + ray-vs-door test. toggle_door flips target on E. door_allows_passage tells the DDA whether a ray hit a retracted slit.

🎨
door_draw_bonus.c

Drawing. When a ray does stop on a panel, this file warps the texture so the door image compresses to the unopened side.

The animation loop is delta-time, not frame count

Every frame, update_doors measures the wall-clock milliseconds since last call and nudges every door by DOOR_SPEED × Δt. On a fast machine the increment is small; on a slow one it's bigger. Either way the door opens in about 555 ms because DOOR_SPEED = 0.0018 means full travel at that rate of progress per millisecond.

CODE — doors_bonus.c:91 
void	update_doors(t_cub *cub)
{
	long	now;
	double	step;
	int	i;
	int	n;

	now = now_ms();
	if (cub->door_last_ms == 0)
		cub->door_last_ms = now;
	step = (double)(now - cub->door_last_ms) * DOOR_SPEED;
	cub->door_last_ms = now;
	if (!cub->doors)
		return ;
	n = cub->map.width * cub->map.height;
	i = -1;
	while (++i < n)
	{
		if (cub->doors[i].target == 1 && cub->doors[i].progress < 1.0)
			cub->doors[i].progress = fmin(1.0, cub->doors[i].progress + step);
		else if (cub->doors[i].target == 0 && cub->doors[i].progress > 0.0)
			cub->doors[i].progress = fmax(0.0, cub->doors[i].progress - step);
	}
}
PLAIN ENGLISH

Once per frame, advance every door's progress.

Wall-clock ms via gettimeofday.

First frame: seed the previous-time anchor.

step = elapsed ms × DOOR_SPEED. Frame-rate independent.

Slide the anchor forward.

No door grid? bail.

Walk every cell in the flat grid.

Target is "open" and we're not there yet → step up, clamp at 1.

Target is "closed" and we're not there yet → step down, clamp at 0.

⏱️
Why delta-time and not "+0.01 per frame"?

If you increment by a fixed amount per frame, animation speed is tied to FPS — fast machine, fast doors. Multiplying elapsed milliseconds by a per-ms rate gives wall-clock-consistent animation. Same door, same 555 ms, any machine.

Toggling on E

The player presses E. The hook computes the cell DOOR_REACH = 1.5 cells ahead. If that's a door, flip its target. The one guard: if you're standing on the door cell, refuse to start closing it — no crushing the player.

{
	int	fx;
	int	fy;
	t_door	*d;

	fx = (int)(cub->player.pos_x + cub->player.dir_x * DOOR_REACH);
	fy = (int)(cub->player.pos_y + cub->player.dir_y * DOOR_REACH);
	d = door_at(cub, fy, fx);
	if (!d)
		return ;
	if (d->target == 1 && fx == (int)cub->player.pos_x
		&& fy == (int)cub->player.pos_y)
		return ;
	if (d->target == 1)
		d->target = 0;
	else
		d->target = 1;
}

The key idea: a sliding center band

Picture the door face as a 1-unit-wide strip. The two halves of the door panel slide apart from the middle. At progress p, a slit of total width p sits centered on the door face — the open band is the interval [0.5 − p/2, 0.5 + p/2]. Any ray that hits that band should pass through. Any ray that hits the still-solid sides should stop and render the door texture.

🚪
The band math

hit ∈ ( 0.5 − p/2 , 0.5 + p/2 ) → pass through
else → panel hit

At p = 0 the band is empty — door fully solid. At p = 1 the band is the whole face — door fully open. Linear in between.

door_allows_passage implements that band

CODE — door_use_bonus.c:60 
int	door_allows_passage(t_cub *cub, int y, int x, double hit)
{
	double	p;

	p = door_progress_at(cub, y, x);
	if (p <= 0.0)
		return (0);
	if (p >= 1.0)
		return (1);
	return (hit > 0.5 - p * 0.5 && hit < 0.5 + p * 0.5);
}
PLAIN ENGLISH

For a ray hitting door at cell (y, x) with hit fraction (0..1), does the ray pass?

Look up the door's current animation progress.

Fully closed → never pass.

Fully open → always pass.

Mid-animation → pass only if hit lies in the central retracted band.

Texturing the visible panel — warp_door_wx

When the ray does stop on a panel, we have a problem: the panel is now narrower than the full cell face, but we still want to draw the entire door image on it (compressed). The warp function squashes the raw hit coordinate into the appropriate side.

↔️
The panel-width formula

panel_width = 0.5 − progress / 2

Each side of the door starts at 0.5 wide (half the cell) and shrinks by p/2 as the door opens. At p = 0 each side is 0.5 wide; at p = 1 each is 0. Two pieces, symmetric.

CODE — door_draw_bonus.c:35 
static double	warp_door_wx(double wx, double progress)
{
	double	half;
	double	panel;

	if (progress <= 0.0 || progress >= 1.0)
		return (wx);
	half = progress * 0.5;
	panel = 0.5 - half;
	if (panel <= 1e-6)
		return (wx);
	if (wx < 0.5)
		return ((wx / panel) * 0.5);
	return (0.5 + ((wx - (0.5 + half)) / panel) * 0.5);
}
PLAIN ENGLISH

Squash raw hit coord (0..1) onto the visible panel's texture coords.

Fully closed or fully open → no warp needed.

Half of the open gap.

Width of one remaining panel side.

Panel is essentially gone → don't divide by ~0.

Ray hit the left panel?

Stretch [0, panel] back onto [0, 0.5] of the texture.

Right panel: stretch [0.5+half, 1] onto [0.5, 1].

Two thresholds you must keep separate

👁️

Rays pass through at any p > 0

As soon as the door starts opening, the visual slit is real. Rays inside the band continue. That's what makes the see-through-while-opening effect.

🚶

The player only walks through at p ≥ 0.90

door_is_open compares against DOOR_PASSABLE = 0.90. Without this, you'd squeeze through a 5% gap. Visual ≠ collision.
