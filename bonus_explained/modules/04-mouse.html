Module 4 · Mouse look

Catch every pixel of horizontal travel. Spin the view.

Mouse-look in cub3D is three small ideas glued together. The motion hook just collects raw pointer movement into a counter. A focus guard prevents giant jumps when you alt-tab back. The per-frame loop drains the counter and feeds it to the same rotate_vectors the keyboard uses. No cursor warp, no cursor hide, no DPI surprises.

The design constraint: don't break the X close button

A lot of FPS engines hide the cursor and re-center it every frame so they can read relative motion. That breaks two things on Linux/MiniLibX: you can't click the window's × to quit, and refocus from the terminal sends one wild motion event with hundreds of pixels of "delta" from wherever the cursor sat in the meantime.

🖱️
Three rules

1. Never warp the cursor. 2. Never hide the cursor. 3. The first motion after focus only seeds the baseline — it does not rotate.

State lives in t_cub

mouse_last_x The X coordinate of the previous MotionNotify event. Used to compute the delta.
mouse_dx Accumulated horizontal pixels since the last frame. Drained to zero every frame.
mouse_ready Latch. 0 means "next motion event just seeds the baseline." Cleared on focus loss.

The motion hook accumulates deltas

MotionNotify (X event 6) fires for every pixel the mouse moves over the window. The hook does nothing fancy — it just subtracts the previous X from the current X and adds the result to the running total.

CODE — mouse_bonus.c:32 
int	mouse_move(int x, int y, void *param)
{
	t_cub	*cub;

	(void)y;
	cub = (t_cub *)param;
	if (x < 0 || x >= WIN_W)
		return (0);
	if (!cub->mouse_ready)
	{
		cub->mouse_ready = 1;
		cub->mouse_last_x = x;
		return (0);
	}
	cub->mouse_dx += (x - cub->mouse_last_x);
	cub->mouse_last_x = x;
	return (0);
}
PLAIN ENGLISH

X11 calls this for every pixel of mouse movement inside the window.

Vertical movement is ignored — only horizontal turns the view.

Out-of-window event (happens during refocus) → ignore.

Focus events reset the latch

When you alt-tab to your terminal, your cursor moves around without the cub3D window seeing it. The instant you alt-tab back, X11 sends one MotionNotify whose delta from mouse_last_x could be hundreds of pixels — that would spin the view violently. FocusIn / FocusOut both clear mouse_ready so the next event is treated as a fresh baseline instead of a delta.

CODE — mouse_bonus.c:57 
int	focus_in(void *param)
{
	t_cub	*cub;

	cub = (t_cub *)param;
	cub->mouse_ready = 0;
	cub->mouse_dx = 0;
	return (0);
}
PLAIN ENGLISH

X11 calls this when the cub3D window gains focus.

Disarm the latch so the next motion seeds, not rotates.

Throw away any leftover unprocessed delta.

The per-frame drain

Once per frame, apply_mouse_look turns the accumulated pixel count into a rotation. Reusing rotate_vectors means mouse and keyboard turning are mathematically identical — same matrix, same outcome.

CODE — mouse_bonus.c:88 
void	apply_mouse_look(t_cub *cub)
{
	if (!cub->mouse_ready || cub->mouse_dx == 0)
		return ;
	rotate_vectors(&cub->player, (double)cub->mouse_dx * MOUSE_SENS);
	cub->mouse_dx = 0;
}
PLAIN ENGLISH

Called from loop_hook every frame.

No baseline yet, or no movement to apply → bail.

Rotate by (pixels) × (radians per pixel). MOUSE_SENS = 0.0025.

Drain the accumulator — next frame starts fresh.

⚙️
Why accumulate, not "use last event"?

Multiple MotionNotify events can land between two frames — a fast flick might fire 30 events in 16 ms. If you only used the most recent delta you'd throw away 29/30 of the motion. The accumulator captures all of it; the per-frame drain rotates by the total.

Wiring it all up

register_mouse hooks three X11 events: MotionNotify (6), FocusIn (9), FocusOut (10). The masks 1L << 6 and 1L << 21 are X11's PointerMotionMask and FocusChangeMask.

CODE — mouse_bonus.c:103 
void	register_mouse(t_cub *cub)
{
	mlx_hook(cub->win, 6, 1L << 6, mouse_move, cub);
	mlx_hook(cub->win, 9, 1L << 21, focus_in, cub);
	mlx_hook(cub->win, 10, 1L << 21, focus_out, cub);
}

Called at startup from register_hooks.

Subscribe to MotionNotify with PointerMotionMask.

Subscribe to FocusIn with FocusChangeMask.

Subscribe to FocusOut with the same mask.
