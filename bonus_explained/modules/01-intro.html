Module 1 · The big picture

A flat grid pretending to be a world.

cub3D is a tiny first-person 3D maze built on top of a 2D map. There are no polygons, no GPU, no real 3D. Every wall you see in the window is drawn one vertical stripe at a time from a top-down floor plan.

What you actually see when you launch the bonus build

🖱️

The cursor stays visible (so you can still click the X to close), but moving the mouse horizontally rotates your view.

The trick: cast one ray per screen column.

Your window is 1280 px wide. The renderer does not draw triangles — it shoots 1280 imaginary beams straight out from your eyeball into the 2D map, one for each pixel-column on screen. Each beam walks across the grid until it bumps into a wall. The distance it traveled decides how tall that one stripe of wall looks.

💡
Why this still matters in 2026

Raycasting is the canonical first project for understanding 3D graphics from scratch. Modern engines hide cameras, projections, and depth buffers behind layers of abstraction. cub3D forces you to build all three by hand — in roughly 1500 lines of C.

The whole frame is six function calls

Open src_bonus/render/render.c. The entire game loop fits on screen. Every other file we look at in this course is something this hook delegates to.

CODE — render.c:53 
int	loop_hook(void *param)
{
	t_cub	*cub;

	cub = (t_cub *)param;
	apply_movement(cub);
	apply_rotation(cub);
	apply_mouse_look(cub);
	update_doors(cub);
	update_horizon(cub);
	render_frame(cub);
	return (0);
}
PLAIN ENGLISH

This function runs once per frame — MiniLibX calls it for you, forever.

cub is the giant state struct: player position, map, textures, doors, everything.

Step 1: read held WASD keys → nudge the player's position.

Step 2: read held arrow keys → rotate the view.

Step 3: read the accumulated mouse delta → rotate the view some more.

Step 4: advance every door's open/close animation by one tick.

Step 5: update the head-bob offset so the horizon sways while you walk.

Step 6: actually paint the frame — raycast, sprites, minimap, blit.

Return 0 so MiniLibX keeps calling us next frame.
