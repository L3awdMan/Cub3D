Module 11 · Projectiles & combat

Two ways to deal damage: a flying ball, and an instant ray under your crosshair.

Combat splits cleanly in two directions. Enemy → player is a travelling projectile (you can see it coming and dodge). Player → enemy is hitscan: the moment you click, the nearest enemy under the crosshair dies, if a wall isn't in the way. This module covers the projectile pool, the aim-band hitscan, and the weapon HUD that ties the trigger to the screen.

Enemy fire: ball or invisible chip

Back in the AI, enemy_fire() branches on whether the enemy's role has projectile art. Most do — they launch a shot. The fluid alien (empty projectile list, remember Module 9) has none, so it chips your HP instantly and invisibly.

CODE — enemy_ai_bonus.c:66 
static void	enemy_fire(t_cub *cub, t_sprite *s)
{
	if (cub->sprite_anims[proj_type(s->type)].count > 0)
	{
		spawn_projectile(cub, s);
		return ;
	}
	cub->player.hp -= player_dmg(cub);
	if (cub->player.hp < 0)
		cub->player.hp = 0;
	cub->player.hurt_ms = now_ms();
}

⚡
player_dmg(cub), not a constant

Both damage paths (the projectile impact and the invisible chip) call player_dmg(cub), which scales the base ATTACK_DMG by the chosen difficulty. That's the single hook where Easy / Skilled / Gigachad change how hard you get hit — we'll see it in Module 13.

The projectile pool

Projectiles never touch the heap. cub->projectiles[] is a fixed array of MAX_PROJ (32) slots, each with an active flag. spawn_projectile() finds the first free slot, sets its position to the enemy and its velocity to the unit direction toward you × PROJ_SPD. If all 32 are busy, the shot is simply dropped.

1
Spawn

Claim a free slot, aim it at the player's current position, tag it with the firing role's proj_type art.

2
Fly & test

step_one() advances each active shot, expires it on a wall / closed door, or on reaching you (within PROJ_HIT_DIST) deals player_dmg.

3
Draw

draw_one_proj() wraps the shot in a temporary t_sprite and reuses the whole sprite pipeline.

CODE — projectile_bonus.c:78 
static void	step_one(t_cub *cub, t_proj *p)
{
	p->x += p->dx;
	p->y += p->dy;
	if (proj_blocked(cub, p->x, p->y))
	{
		p->active = 0;
		return ;
	}
	dx = cub->player.pos_x - p->x;
	dy = cub->player.pos_y - p->y;
	if (dx * dx + dy * dy > PROJ_HIT_DIST * PROJ_HIT_DIST)
		return ;
	p->active = 0;
	cub->player.hp -= player_dmg(cub);
	if (cub->player.hp < 0)
		cub->player.hp = 0;
	cub->player.hurt_ms = now_ms();
}

💡
Drawing a projectile = drawing a sprite

This is a lovely bit of reuse. draw_one_proj() builds a throwaway t_sprite from the projectile, calls the exact same sprite_transform() and draw_sprite_cols() from Module 8 — so walls occlude projectiles for free. The only override is proj_rect(), which centres the billboard on the horizon (eye level) instead of the floor line, so the ball flies at you rather than rolling on the ground.

Player hitscan — the aim band

When you fire, shoot_hitscan() doesn't trace a literal ray. Instead it projects every alive enemy into camera space (same inverse-matrix maths as the sprite pass), and keeps the ones that pass three gates. The nearest survivor takes the hit.

CODE — enemy_bonus.c:59 
static int	enemy_candidate(t_cub *cub, int i, double *bestd)
{
	if (cub->sprites[i].type >= SP_PICKUP
		|| cub->sprites[i].state == SP_DYING)
		return (0);
	depth = enemy_project(cub, &cub->sprites[i], &col);
	if (depth <= 0.0 || depth >= *bestd)
		return (0);
	if (col < WIN_W / 2 - SHOT_AIM || col > WIN_W / 2 + SHOT_AIM)
		return (0);
	if (depth > cub->zbuf[col])
		return (0);
	*bestd = depth;
	return (1);
}
PLAIN ENGLISH

Is enemy i a valid target for this shot?

Skip pickups...

...and anything already dying.

Project it: get its depth + screen column.

Gate 1: in front of us, and nearer than the best so far.

Gate 2: its column sits inside the centred aim band (±SHOT_AIM).

Gate 3: not hidden behind a wall (compare to the z-buffer).

New nearest valid target → remember its depth...

...and report a hit.

⚡
Hitscan depends on last frame's z-buffer

Gate 3 reads cub->zbuf[col] — the wall depth from the rendering pass. That's why you can't shoot enemies through walls: if the wall in that column is nearer than the enemy, the candidate is rejected. It's the same buffer the sprite blitter uses for occlusion, doing double duty as the "can I hit this?" test.

The caller, shoot_hitscan(), loops every sprite tracking the nearest candidate (bestd starts at SHOT_RANGE), then decrements that enemy's HP. If HP hits zero it flips to SP_DYING, decrements the lives counter, and — unless it's the boss — drops a meat reward. Miss everything and the shot is silent; nothing happens.

The weapon HUD — trigger to pixels

update_weapon() is the per-frame trigger clock. A held SPACE or a left-click (flagged by the weapon_fire button hook) starts a shot: it sets firing, stamps fire_ms, and fires the hitscan once. The five-frame animation then plays for WPN_FIRE_MS before snapping back to idle.

CODE — weapon_draw_bonus.c:59 
void	update_weapon(t_cub *cub)
{
	w = &cub->weapon;
	now = now_ms();
	if ((cub->keys[KEY_SPACE] || w->shoot) && !w->firing)
	{
		w->firing = 1;
		w->fire_ms = now;
		shoot_hitscan(cub);
	}
	w->shoot = 0;
	if (w->firing && now - w->fire_ms >= WPN_FIRE_MS)
		w->firing = 0;
}

The !w->firing guard is the rate limiter: you can't start a new shot until the current animation finishes, so holding the trigger fires at a fixed cadence. draw_weapon_img() then picks the frame, trims the transparent border with frame_bbox(), scales it to WPN_SCALE of the window width, and blits it centred along the bottom edge.

Picking up weapons

Stepping on a PICKUP_CHARS ("789P") tile swaps your weapon. weapon_pickup() reads the tile letter, sets weapon.current to its index + 1, removes the floor sprite, and clears the tile so it can't be grabbed twice. There are five weapons (index 0 is the starting pistol).
